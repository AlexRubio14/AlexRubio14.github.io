01 | My Role

Lyra was developed by La Mapachanda, a seven-person multidisciplinary team. My role combined two areas that had to work closely together: Character Programming and Production.

Character Programming
  • Character controller and movement systems
  • Camera-relative locomotion
  • Character state architecture
  • Enhanced Input integration
  • Companion interaction systems
  • Animation and gameplay integration
Production
  • Scrumban planning and sprint coordination
  • Milestone and roadmap tracking
  • Cross-discipline communication
  • Perforce workflow
  • Jenkins CI/CD pipeline
I wasn't only implementing gameplay — I was also responsible for keeping the team moving towards the final build.

02 | Character Architecture

The Problem: As character interactions grew, movement, companion actions and gameplay states could easily become coupled through boolean flags and conditional logic. I wanted each character state to own its behaviour instead of having the character controller decide what should happen through a growing set of conditions.

The Solution: I designed a modular Finite State Machine where each state follows a common interface and explicitly controls its own lifecycle.

Engineering Decisions:
• State Encapsulation: Each state owns the behaviour associated with its lifecycle (OnEnter, OnUpdate, OnExit).
• Interfaces: States communicate through defined contracts rather than depending directly on concrete implementations.
• Design Patterns: State • Strategy • Observer • Mediator.

04 | Companion System

The companion system is one of Lyra's core gameplay mechanics. The player can invoke, pick up, aim and throw dragons to interact with the environment and solve environmental puzzles.

PICK UP
AIM

Input Architecture: Different character states require different available inputs. Instead of keeping every action permanently active, Lyra dynamically switches Input Mapping Contexts (IMC) depending on the current character state.

Attachment & Animation: When a dragon is picked up, its attachment to the character's skeletal mesh is synchronized with animation events. Sockets provide the attachment point, while animation notifies coordinate the moment when the gameplay state changes.

05 | Camera-Relative Locomotion

Lyra uses fixed cameras placed along rails, with smooth transitions between viewpoints. During a camera transition, world-space movement can make the player's controls feel inconsistent with what the player sees.

Solution: Movement input is calculated relative to the active camera (Camera Forward) instead of directly using absolute world-space directions, ensuring input direction remains intuitive while the camera changes.

06 | Production Pipeline

Working within a real production meant adopting industry-standard version control and tracking pipelines tailored for Unreal Engine projects.

  • Scrumban: Organized using weekly sprints, milestone tracking and cross-discipline coordination via Jira and Confluence across programming, design, art and animation.
  • Perforce Helix Core: Configured with exclusive checkout policies for .uasset files to reduce conflicting binary edits and make asset ownership explicit.

07 | CI/CD & Nightly Builds

To keep the team working against a reproducible build, I configured a Jenkins CI pipeline for automated nightly builds, ensuring synchronization, compilation, cooking and packaging run reliably.
